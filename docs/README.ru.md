# ihar

[Английская версия](../README.md)

`ihar` — локальный слой управления Claude Code и Codex CLI по единой политике
проекта. Он полезен разработчикам и командам, которые переключаются между агентами
и не хотят отдельно поддерживать для каждого правила безопасности, подключения MCP
и список сессий.

`ihar` запускает собственные бинарные файлы `claude` и `codex` поставщиков, не
изменяя и не заменяя их. Учётные записи, авторизация и история диалогов остаются у
поставщиков; `ihar` обеспечивает общую настройку вокруг них. Отдельная учётная
запись ihar и облачный сервис агентов не нужны.

## Зачем использовать

Обычно два агента означают два формата конфигурации, две системы хуков и разные
модели изоляции. `ihar` даёт проекту единую точку запуска, общий индекс сессий и
ограниченную передачу очищенного контекста при переходе между агентами. Общие
профили создают настройки безопасности для каждого поставщика. Профиль с
принудительными гарантиями должен подтвердить их перед запуском, иначе запуск
прекращается; профиль `standard` намеренно не даёт таких гарантий.

Это уменьшает дублирование настройки и риск расхождения политик, сохраняя привычную
работу с нативными агентами. `ihar` не является новой моделью, средой выполнения
агента, хранилищем переписок или заменой подписок поставщиков.

## Гарантии профилей

Профиль задаёт набор гарантий. Команда `ihar check` показывает, какие из них
действуют.

| Профиль | Действующие условия |
|---|---|
| `standard` | Хуки дают рекомендации. Управления сетью нет. Действуют настройки поставщика и единая конфигурация проекта. |
| `protected` | Хуки применяются принудительно. Запросы к модели проходят через локальный шлюз, который маскирует секреты и отклоняет содержимое, которое не может обработать. MCP-серверы ограничены списком разрешённых в реестре. |
| `isolated` | Условия `protected` плюс запуск внутри microVM. |

Если принудительную гарантию нельзя подтвердить, агент не запускается. Тихого
ослабления профиля нет.

## Установка

Компоненты устанавливаются для текущего пользователя; установке не нужен `sudo`.
Для запуска профиля `isolated` нужен беспарольный `sudo`, чтобы создавать временный
TAP-интерфейс и правила межсетевого экрана. После завершения запуска они удаляются.

```bash
git clone https://github.com/ikeniborn/ihar.git ihar
cd ihar
./ihar.sh install
```

Установка подготавливает хранилище, создаёт команду `ihar` в `~/.local/bin` и
окружение Python, устанавливает закреплённые версии компонентов, проверяет архив
Codex по сохранённому хешу и пытается выполнить полный набор live-проверок хуков.
Версия Node/Claude закреплена, но хеш архива Claude не указан в lockfile.

При первой установке отсутствие нативной авторизации поставщика может оставить одного
или нескольких поставщиков без подтверждения после корректной установки. Установщик
всё равно активирует такой bootstrap, называет поставщика и имена не пройденных
обязательных проверок, но не выводит ответ поставщика или учётные данные, и предлагает
после входа через штатный сценарий поставщика выполнить `ihar check --conformance`.
`standard` по-прежнему запускается с нативной авторизацией; профиль с принудительными
гарантиями отказывает до запуска поставщика, пока нет полного совпадающего доказательства
conformance. При установке или обновлении существующего поколения иначе: неудачная или
неполная live-проверка отменяет активацию и сохраняет прежнее поколение, receipt и записи
подтверждения.

Явная повторная проверка отзывает прежнее управляемое доказательство для каждого
проверяемого поставщика. При сбое защищённый профиль остаётся закрытым до успешной
следующей проверки этого поставщика.

Специально подготовленный гостевой образ Firecracker берётся из совместимого
локального каталога. Файлы `firecracker`, `vmlinux` и `rootfs.ext4` проверяются по
хешам из lockfile. Три файла SSH-ключей проверяются по формату и соответствию друг
другу; их хеши в lockfile не закреплены. Версия образа выводится из трёх
закреплённых хешей. Новая версия сначала подготавливается, затем указатель на
текущую версию и ссылки команд обновляются с возможностью отката:

```bash
IHAR_MICROVM_SOURCE_DIR=/path/to/assets ./ihar.sh install --microvm
```

Если `~/.local/bin` отсутствует в `PATH`, установщик сообщит об этом. Добавьте
каталог:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

## Использование

```bash
ihar claude
ihar codex
ihar --profile protected codex
ihar check
ihar --dry-run --profile protected codex
ihar sessions list
ihar sessions resume <ihar-id>
ihar switch --to codex
ihar web claude
ihar --profile protected codex --web
```

Всё после `--` передаётся агенту без изменений:

```bash
ihar codex -- mcp list
```

Полный список команд и флагов показывает `ihar --help`.

Команда `ihar sessions list` объединяет метаданные сессий из хранилищ обоих
поставщиков в индекс проекта. Содержимое переписок в индексе не хранится. Для
продолжения используйте постоянный `ihar-id` с `sessions resume`; для изменения
локального названия — `sessions name <ihar-id> <title>`.

Команда `ihar switch --to claude|codex` создаёт ограниченный по размеру пакет
контекста с маскированием, связывает записи двух сессий и запускает другого агента.
Claude получает пакет в начальном запросе, Codex однократно читает оставшуюся
часть через хук SessionStart.

Флаг `--history summary|transcript` задаёт, сколько переписки уходит дальше.
Режим `summary` используется по умолчанию и отправляет только пакет. Режим
`transcript` дополнительно записывает историю исходной сессии в маскированный файл
рядом с пакетом и указывает на него следующему агенту, чтобы тот прочитал историю,
если пакета недостаточно:

```bash
ihar switch --to codex --history transcript
```

Ни один поставщик не принимает чужую сессию, поэтому история приходит файлом,
который агент может прочитать, а не состоянием, которое он возобновляет. Такие
файлы сохраняются до тех пор, пока вы их не удалите; `ihar check` показывает их
количество и занятый объём.

## Веб-доступ сейчас

Запускайте `ihar web` на компьютере, где находятся проект и авторизация агента.
На текущем этапе `ihar` — локальный клиент запуска, а не отдельный сайт или
облачный сервис ihar. Команда включает собственный удалённый интерфейс
поставщика; доступ к той же нативной сессии выполняется через его сопряжение
или браузерный сценарий.

```bash
ihar web claude
ihar web codex
```

Команды `ihar claude --web` и `ihar codex --web` эквивалентны. Claude Remote
Control работает только с `standard`: профиль `protected` отказывает в запуске,
поскольку его шлюз запросов к модели несовместим с этой функцией поставщика.
Codex работает с `standard` и `protected`: `ihar` запускает управляемый демон
app-server, показывает код сопряжения и подключает к нему терминальный клиент.
Профиль `isolated` не предлагает ни один из этих веб-режимов.

Эти мосты принадлежат поставщику, и каждый обслуживает одну сессию. Порядок
подключения конкретного поставщика и необязательный аутентифицированный
LAN-слушатель Codex описаны в [руководстве по веб-доступу](manual/web-surfaces.md).

## Консоль нескольких сессий

Команда `ihar console start` запускает локальный брокер, который создаёт сессии ihar
и отдаёт их терминалы в одном месте — по всем проектам на машине:

```bash
ihar console start
ihar console status
ihar console stop
```

Команда печатает адрес вида `http://127.0.0.1:<port>/?t=<token>`. Слушатель работает
только на loopback — bind на сетевой адрес отклоняется, а не понижается, — поэтому
доступ с другой машины выполняется через SSH-туннель. Токен однократно обменивается
на cookie с флагом `HttpOnly`; он требуется каждому запросу, а WebSocket дополнительно
проверяет Origin.

Каждая вкладка запускает обычный CLI под псевдотерминалом, то есть вкладка — это
обычный запуск: профиль, его хуки, шлюз и песочница действуют без изменений, а проект
с `console: refuse` в профиле получает отказ только в своей вкладке. Профили
`standard` и `protected` разрешают консоль, `isolated` запрещает, поскольку его сессия
исполняется внутри гостя.

Вывод терминала никогда не пишется на диск: он хранится в ограниченном буфере в памяти
и воспроизводится при повторном подключении браузера. Вкладка переживает брокер,
поэтому перезапуск консоли или обновление ihar не убивает запущенных в ней агентов.

Брокер также отдаёт то, что будет показано в окне: единый список всех проектов машины
с поставщиком, названием, профилем и текущим состоянием каждой сессии, и
только-читаемую ленту, которая проходит через `switch` между поставщиками и отмечает
место, где handoff обрезал контекст. Сессия, которой больше нет в хранилище
поставщика, показывается помеченным пропуском, а не выдуманным текстом, — копии у ihar
нет. Состояния приходят от хука на четырёх событиях жизненного цикла, общих для обоих
агентов: работает, ждёт подтверждения, простаивает, остановлена, — поэтому список
показывает, какой агент ждёт вас.

Откройте напечатанный адрес — и окно покажет всё сразу: боковую панель со всеми
проектами и их сессиями, вкладку на каждого работающего агента с его собственным
терминалом, панель истории, читающую цепочку через `switch`, панель с выводом
`ihar check` для этого проекта и кнопки переименования сессии и передачи её другому
агенту. Браузерные уведомления, если их разрешить, сообщат, что сессия ждёт вас.

Вкладка бывает двух видов. По умолчанию — собственный терминал агента, профиль
действует без изменений. Второй вид — экспериментальный чат по ACP: он предлагается
только там, где профиль разрешает ACP, поэтому `protected` и `isolated` отказывают, и
сама вкладка пишет, чего она не несёт: хуки, которые под адаптером Claude могут не
срабатывать, песочницу и политику подтверждений, которые подменяет адаптер Codex, и
отказ консоли давать агенту файловую систему или терминал через браузер. Это те же три
строки, что печатает `ihar check`. Запрос подтверждения от агента показывается и ждёт
вас — за вас на него никто не отвечает.

Может ли этот чат перестать быть экспериментальным — вопрос измерения, а не мнения, и
его задаёт одна команда:

```bash
ihar check --acp-promotion
```

Она читает условие из манифеста, сообщает по каждой части «выполнено», «не выполнено» или
«не измерено» и отказывается говорить «можно продвигать», пока хоть что-то не измерено.
Профили она не меняет. На сегодня ответ — *not promotable*: названные ею задачи в апстриме
всё ещё открыты.

Всё, что загружает страница, брокер отдаёт из закреплённой копии: терминал — это
`xterm.js` 5.5.0, приложенный вместе с его digest в lockfile выпуска, и сборка с
другими байтами будет отклонена, а не отдана. Ничего не скачивается из сети, поэтому
консоль работает на машине без интернета.

Одно ограничение стоит назвать прямо: токен консоли запускает сессии в любом состоянии
проекта на этой машине — это шире, чем один запуск. `ihar check` печатает эту
досягаемость, и окно тоже.

## Настройка

Настройки проекта находятся в файле `.ihar_config` в корне проекта. Скопируйте
пример и отредактируйте его:

```bash
cp .ihar_config.example .ihar_config
```

Файл разбирается как данные, а не выполняется как скрипт: допустимы только
присваивания `IHAR_*`, неизвестный ключ вызывает ошибку, значение не исполняется.
Приоритет: значения по умолчанию, затем файл, затем флаги командной строки.
Исключение — минимальный уровень маскирования профиля: файл и флаги не могут его
понизить. Все строки примера закомментированы. Значения `${…}`, `unset` и
`the profile's floor` поясняют умолчания; перед раскомментированием замените их
конкретными допустимыми значениями, а не копируйте буквально.

## Обновление

```bash
ihar update
```

Установка и обновление используют одну транзакцию; lockfile остаётся неизменяемым
источником закреплённых версий. Если отметка версии совпадает, повторное скачивание
или установка бинарного файла поставщика может быть пропущена. Но каждый запуск
всё равно проверяет структуру ресурсов, подготавливает и копирует объявленные
ресурсы, повторяет проверки соответствия, создаёт новое подтверждение установки
и активирует подготовленное поколение. Неизменный lockfile не превращает команду
в пустое действие. Новая версия бинарного файла требует новой проверки, потому
что свидетельство привязано к его хешу. Исключение для неподтверждённого conformance
есть только при первом bootstrap; существующее поколение всегда откатывается при
неудачной или неполной проверке.

## Требования

Linux или macOS, Bash 5, Python 3.11 или новее, `flock`, `curl` либо `wget`.
